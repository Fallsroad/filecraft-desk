How to tell whether a cleaned spreadsheet is actually clean

A cleaned file is only worth paying for if you can check it. Run these five checks, using our own 500-row demo run as the example.

  1. The rows reconcile. 500 rows in, 60 removed (30 exact and 30 fuzzy duplicates, matched on email), 440 out. 500 - 60 = 440. If the arithmetic is not shown, the file was edited, not checked.

  2. Removed rows are listed, not vanished. Each one comes back on its own sheet, with the reason it was removed.

  3. Every change is logged. The demo run changed 2,031 cells, each one written in a change log with the before and after value.

  4. Invalid data is flagged, never guessed. 74 email addresses in the demo were not valid emails. They stayed in the file, marked. Nobody invented a corrected address.

  5. Leftovers are named. Anything that could not be fixed stays as given, and the report says so. In the demo, zero phone numbers had to be left as-is, and the report has a line for them either way.

That is how FileCraft Desk cleans spreadsheets and CRM exports: fixed prices, a run report with counts that reconcile on every order, and the change log and removed-rows sheet on the standard tier and up.

Check your sending domain in five minutes

Four public DNS records decide whether cold email from a new domain lands in the inbox or in spam. You can read all four from outside, with no login. Here they are, with the results from a real domain we verified.

  • MX: the domain publishes mail servers. Example: PASS (Google Workspace).

  • SPF: exactly one record starting v=spf1, naming who may send for the domain. Two records is a fail. Example: PASS (one record, authorizing Google).

  • DKIM: a public key at <selector>._domainkey.<domain>, so receivers can verify the sending service signed the mail. Example: PASS (key at the Google selector).

  • DMARC: a record at _dmarc.<domain> starting v=DMARC1. Example: PASS, with the limit stated plainly: the policy is p=none, monitor only. Failing mail gets reported, not blocked. Anyone who calls p=none full protection is not telling you the whole story.

FileCraft Desk sets up cold email infrastructure at a fixed price the same way: we never ask for your logins. You get the exact records as a change sheet, you add them in your own DNS panel, and we verify the result from public DNS.
